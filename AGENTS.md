# Outtake

Plex clip manager. Go 1.27, Fiber v3, templ, HTMX, Cobra. App code lives under `internal/` (no `pkg/`). Composition root: `internal/app`. CLI: `internal/cmd`. Entrypoint: `main.go`.

## Commands

Taskfile, not Make. golangci config: `build/golangci-lint/golangci-lint.yaml`.

```bash
task templ          # required before lint/test/vet
task lint           # golangci-lint --fix
task lint-ci        # no --fix (what CI runs)
task vet            # go vet, then go vet -tags e2e over testing/e2e
task test           # -race over ./..., then the coverage gate
task run            # go run . server start
task templ-watch    # templ proxy → :8080, cmd is server start
task compose-dev    # docker compose up --build
task mock           # mockery, then goimports over every mocks/ directory
task docs           # regenerate docs/content/cli-reference with tools/docgen
task docs:build     # build the Hugo site into docs/public
task docs:serve     # preview the site with live reload
```

Validate with `task lint-ci` then `task vet`, not `go build`. Single package: `go test ./internal/ffmpeg -run TestFoo` after `task templ`.

Server CLI is `outtake server start` (or `go run . server start`), not `serve`. Default listen `:8080`. Do not add a templ `:8080`→`:8090` proxy or a `docker-compose.dev.yml` overlay; one `docker-compose.yml` plus `.env`.

## Generated code

templ, goimports, and mockery are `go tool` dependencies pinned in `go.mod`, so the Taskfile, the workflows, and `Dockerfile.dev` all run the same versions through `go tool`. Never `go install` them or call them `@latest`.

The generated `*_templ.go` files are committed. `task templ` is `go tool templ generate` then `go tool goimports -local github.com/PapagoLabs/outtake -w ./internal/web`. Ungrouped imports after generate are fixed by that goimports pass, not by skipping generate. The pass also drops an import a template no longer uses, which `templ generate` alone keeps, so remove it from the `.templ` file: `Dockerfile.dev` and `vet.yaml` run `templ generate` without goimports and fail on it.

Do not add templ/goimports hooks to GoReleaser. CI and `task goreleaser*` already generate first. Do not edit Mockery output; regenerate with `task mock` and commit everything it writes. Its goimports pass groups the mocks' imports the way `task templ` regroups the web mocks, so the two tasks never undo each other.

CSS: `task tailwind` reads `internal/web/assets/css/input.css`.

## Test tiers

Three tiers. Keep a test in the lowest tier that can prove the thing.

- **Unit (white-box)** — `package foo`, `<file>_test.go`, beside the code. testify. Most tests live here.
- **Integration (black-box)** — `package foo_test`, `internal/<domain>/<package>_integration_test.go`. No build tag, so it runs in `go test ./...`. Exercises a package's exported surface against its real collaborators. It must not contact an external service: use `httptest`, `t.TempDir()`, the in-process SQLite in `internal/store/database`, or a mockery mock. `httptest` beats a mock at a process boundary you do not own; a mock beats one you do.
- **E2E** — `//go:build e2e` under `testing/e2e`, one subdirectory per app area, with the shared harness in `testing/e2e/helpers`. Not in `go test ./...`. Needs ffmpeg plus Plex credentials from `testing/e2e/.env` (see `.env.example`). A shell export beats the file. Specs skip cleanly when their prerequisite is absent, so a credential-less run is green, not red.

A test that needs a request to fail aims it at an `httptest` server held for the whole test, whose handler hijacks each connection and closes it unanswered (`dropRequest` in the Plex, identity, and health tests). Never release a free port and dial it later: `go test` runs packages side by side, so another listener can take the port and answer. A test server's handler never blocks on a channel the test reads, because `httptest.Server.Close` waits for every handler.

`internal/web/handlers` and `internal/web/middleware` accept narrow consumer-owned interfaces rather than concrete `*identity.Auth`, so tests drive them with `task mock` output instead of a live Plex. Handler tests that mount a handler without the auth guard record a caller with `middleware/middlewaretest` (`AsOwner`, `AsMember`), because a request without one reaches no clip.

## CI coverage gate

`task test` and `.github/workflows/test.yaml` run `go test -race -count=1 -covermode=atomic -coverprofile=coverage.out ./...`, then `build/ci/coverage-gate.sh coverage.out`. The gate leaves `**/mocks/**` and `*_templ.go` out of the total, because they are scaffolding, and fails when the hand-written code is below the floor the script sets. Raise the floor as coverage improves. Never lower it.

## E2E

There is no `testing/integration` tree. `task test-e2e` runs the e2e suite.

CSRF tokens live in the session, so the harness opens a session for every unsafe request: a GET on `helpers.HandshakePath` (`/login`) mints the token, and the request carries that session's cookies with the token in the CSRF header. `/api/healthz` is mounted before the session middleware and mints nothing. Redirects answer 303 See Other. Compare typed values with their domain constants, such as `clip.StatusCompleted` or `api.NotReady`, and asset URLs with `assets.URL`.

## Docs

No Markdown file is hard-wrapped, including READMEs, this file, and docs: every paragraph and list item is one line, and the viewer wraps it. Code blocks, tables, and the centered HTML header keep their own lines.

The documentation site is a Hugo site under `docs/` with the Hextra theme, published at `https://outtake.papagolabs.com/` by Cloudflare Pages, which builds it from `main`. `docs/` is its own Go module that holds only Hugo modules, so `go test ./...` skips it. Cloudflare also builds a preview for each pull request and reports it as a check, so no workflow builds the site. A page goes up only with its content, never as a placeholder, because every merge to `main` publishes.

The navbar lists the top-level sections, Setup, Guide, Troubleshooting, and CLI Reference, and each page's sidebar lists only its own section's pages. That works because the home page is a Hextra landing page (`layout: hextra-home`), not a docs page, so Hextra roots each sidebar at the page's first section. Add a page inside a section, never at the top level, and give a new section an `_index.md` with `cascade: {type: docs}` and a navbar entry in `docs/hugo.yaml`.

The site uses the app's Plex palette, dark only: `docs/assets/css/custom.css` sets Hextra's colors, and `docs/assets/js/head/theme.js` replaces Hextra's theme script so a theme stored by an earlier visit never applies. Screenshots live in `docs/static/images/screenshots/`, and the README links the same files. They show no Plex artwork and no personal library: take them from a local `outtake server start` with `OUTTAKE_ENV=e2e` on a loopback address, a scratch data directory, and an FFmpeg `testsrc2` pattern as the media, with clips created through `POST /api/clips` using the file path as the media id. Leave out pages that look empty only because no Plex server is connected. Every `OUTTAKE_` variable in `config.envKeys` must appear on `docs/content/setup/configuration.md`, which `TestConfigurationPageNamesEveryVariable` checks.

The CLI reference under `docs/content/cli-reference/` is generated by `tools/docgen` from `cmd.DocRoot`, which builds the command tree without loading any configuration. Run `task docs` after changing any command, its help, or a flag, and commit the pages: `TestDocgenMatchesCommittedReference` fails until you do, and `update-cli-docs.yaml` opens a `docs/update-cli-reference` pull request when `main` changes without them. Settings live in `OUTTAKE_*` environment variables, not flags, so the reference lists only `--listen` and the `version` flags.

## Doc comments

A doc comment opens with one short summary sentence that starts with the declaration's name and a verb, such as "Update applies a validated edit to a clip and saves it." A test's reads "TestFoo covers <the scenario>." Then a line with only `//`, then the details as separate sentences, then the `Parameters:` and `Returns:` sections. The summary never chains its explanation on with a colon or a run of "so", "which", and comma clauses. Comments wrap at 80 columns.

## UI wording style

Web UI text follows the [GNOME HIG writing style](https://developer.gnome.org/hig/guidelines/writing-style.html). Text is classed by how it reads on the page, not by its element. Header capitalization covers anything that reads as a heading or a control's name: page and card titles, headings, a field label on its own line above its control, buttons, links styled as buttons, badges, select options, and tooltips. Sentence capitalization covers text that runs on into a control or other text: a label beside a checkbox or radio button, help text, placeholders, status lines, and messages. Text ends without a period unless it holds more than one sentence. Buttons carry no ellipsis, even one that asks for confirmation first. Name things after what the user sees, such as "preview", not internal terms such as "SDR version". Pages carry no subtitle under their title. Login and Logout are single words everywhere.

## Errors on the page

A handler answers a failure with `respond.WriteFailure` and a `view.Failure`: a plain message and, when it helps, the details. `respond.Fail` picks the message from `failure.Classify`, one table in `internal/failure` keyed on the domain packages' sentinels and typed errors (`clip.SelectionTooLongError`, `clip.PastSourceEndError`, `clip.MissingAudioTrackError`, `timecode.FieldError`, an FFmpeg `*exec.ExitError`), with `failure.MessageUnexpected` for anything unnamed. A `net.Error` reads as Plex being unreachable unless it is a bare `syscall.Errno`, which a local file error such as a full disk carries. `internal/failure` also owns the `ref`, the token scrub, and the Details layout, so pages and renders format details alike. A rule marked as an input refusal shows its message alone. Any other failure is logged with a short `ref` and carries details: the version, time, method and path (never the query), and the error chain, scrubbed of Plex tokens. Only a signed-in session sees details. The banner keeps them in a collapsed Details section with a Copy button, which falls back to selecting the text where the clipboard API is missing. A form post or a followed link that fails is redirected with the failure held in the session (`respond.SetFlash`), never in the address, and the next full page takes it in `respond.RenderHTML` and shows it in the layout's banner slot. An htmx fragment leaves it for that page. JSON callers keep their `error` code, with the plain `message` and a `details` field. Handler tests read the carried failure with `respond/respondtest`.

A failed render is described the same way. The queue and the preview service take a `clip.DescribeFunc` (`SetFailureFunc`), and `app` gives both `failure.Describe`, because the message table imports them and they cannot import it. A failed clip stores its plain message in `clips.error_message` and its details in `clips.error_details` (migration 011), and its card shows the message with the same collapsed Details section. The JSON clip response carries them as `error` and `errorDetails`. A failed preview's status carries `message` and `details`, and the export form's script fills the hidden `flash.DetailsSlot` under its status line. The queue's "job failed" line and the preview service's "preview failed" line carry the `ref`. A clip render checks its source file before FFmpeg (`clip.ErrSourceUnreadable`), and an FFmpeg that never started returns `ffmpeg.ErrNotStarted`, so both get a message that names the setting to check. A canceled render reads "The render was canceled".

## Domain

- Timecode is `internal/timecode` over Clock/FFmpegClock: constructors `FromSeconds` / `FromDuration` / `Parse`, and renderers `Duration` / `Short` / `String` / `FormatSeconds`. Parse through milliseconds. Library duration is HH:MM:SS; clip editing is HH:MM:SS.mmm. It is a top-level leaf: presentation and ffmpeg both depend on it, so nothing imports `internal/ffmpeg` just to format a duration.
- Render a `time.Duration` through `timecode.FromDuration(d).FormatSeconds()`, never `timecode.FormatSeconds(d.Seconds())`. The free `FormatSeconds(float64)` exists for wire seconds off a JSON body; going through it with a `time.Duration` unwraps and re-wraps the primitive for nothing.
- FFmpeg invocation is `internal/ffmpeg` with `probe/`, `crop/`, `progress/`, and `tonemap/` subpackages. Tests fake ffmpeg and ffprobe with `ffmpeg/ffmpegtest`: `ffmpegtest.Install` returns a symlink to the running test binary plus a `Stub` describing what it does, and `ffmpegtest.Dispatch()` goes first in the package's `TestMain` to act the stub out. Never write executable stub scripts, because running a file another parallel test's fork still holds open for writing fails with "text file busy". A `Stub`'s `Cases` answer each kind of call by an argument it carries, such as `framecrc` or `null`, so one fake can stand in for a caller that runs FFmpeg several ways. CI installs no FFmpeg, so a test that runs the real binaries skips there, and the coverage gate counts only what the fakes reach: give code a real-FFmpeg test and a fake-driven one. There is no published ffmpeg interface; callers take `*ffmpeg.ExecFFmpeg`. Name that parameter `runner` in a file that imports the package, so the import is not shadowed.
- ffmpeg children run with working directory `/`. Pass them absolute media paths.
- Every render writes to a `.staging-<uuid><ext>` file beside its output and is moved into place only when ffmpeg succeeds and the file is not empty, so a failed or canceled regenerate keeps the old file. GIF palettes sit beside the staging file. `app` sweeps staging files and palettes nothing has written for an hour from the output directories before any worker starts, so a render another process sharing the storage path is running keeps its file. A render canceled after ffmpeg finished is not published. An empty output path is refused.
- `progress.Writer` parses only what each write adds, keeps a 64 KiB tail of stderr for error logs, and reports a percent only when it changes. `app` records a render's progress at most once a second. A rendering clip's card and a rendering preview's status show the time left (`view.RemainingLabel`), estimated by `clip.Remaining` from the rate since the current encode started: `clip.Job.StageStarted`, which the queue sets when a worker takes the job and again in `SetStage`, and never stores, or a preview's `View.Started`, set when it starts rendering after it gets a slot. There is no estimate below 3% or 5 seconds. The label gives the estimate itself in compact units, recomputed on every poll and rounded only to the second: minutes and seconds under an hour, such as `2m 34s left`, and hours and minutes past it, such as `1h 20m left`, leaving out any part that is zero. A page keeps current over one server-sent event stream, `GET /live` (`handlers/live`), because each stream holds one of the browser's six HTTP/1.1 connections to the server. The query names what the page follows, and each name is a `live.Feed` the router wires: `clip` (rendering clip ids, at most 50, `clip.Handler.LiveClips`), `preview` (a preview id, `preview.Handler.LivePreview`), and `playback` (a media item id, `home.Handler.LivePlayback`). The stream checks every feed each second, sends what changed under the feed's name, and pings after every check. A clip sends its status region rendered the way `/clips/:id/row` does, reading the profiles once and a clip's stored files only when its status or stage changes, because on S3 each is a request. A preview sends the payload its status route answers with, or `gone` once. The playback panel is rendered from the session monitor's cache, so it changes only as often as the monitor polls Plex. The stream ends after a minute, so the browser reconnects through the auth guard and a revoked session or a logout stops it, and the router's `OnPreShutdown` hook calls `live.Handler.CloseStreams`, because the server waits for open connections. `live.js` follows `data-clip-live` regions, a `data-playback-live` panel, and a `data-preview-live` player. It morphs clip regions (`outerMorph`) and the panel (`innerMorph`) in with `htmx.swap` and the element as `sourceElement`, so `app.js`'s swap listener wires them as it does for a poll, and hands preview states to `media-item.js` as `outtake:preview` events. `media-item.js` marks and unmarks the player itself and dispatches `outtake:live-sync`, and its one state handler ignores a state after the render settled and a bar behind the one shown. The stream is open only while the tab is visible and the page follows something, closes on `pagehide`, and reopens whenever what the page follows changes. While an event arrived within 2.5 seconds, `live.js` cancels the poll of each region and panel it follows in `htmx:before:request`, and `media-item.js` skips its preview fetch, and otherwise the polls carry on, as behind a proxy that buffers the stream. A clip bar's width transitions linearly over that second, and a preview's over its 1-second poll. It glides under `prefers-reduced-motion` too, because the bar's growth is the progress itself, not the zoom or panning that preference stops. A morph onto a finished card drops the poll attributes, so the polling stops. `progress.Writer` reports the exact percent, not rounded, so a slow encode's bar still moves on a poll that brings no new whole percent. The worker hands every report to the queue's `TrackProgress`, which keeps it in `clip.Job.ExactProgress` without reporting it, like `StageStarted` never stored, and still reports the whole percent through `SetProgress` at most once a second. A preview keeps it in `View.ExactProgress` and its status sends it as `barPercent`. Bars are drawn from `clip.BarPercent`, which takes the exact percent only while it refines the whole one, and written to a tenth of a percent (`view.BarStyle`). Labels, the database, and the JSON clip response keep the whole percent.
- SQLite opens through the `modernc.org/sqlite` DSN with WAL, `busy_timeout(5000)`, `synchronous(NORMAL)`, and immediate transactions, on a pool of four connections.
- `blob.Blob` has `Exists`, which never downloads, and `Ensure`, which downloads only a missing local copy. Cards and badges use `Exists`. Playback, download, previews, and the thumbnail cache use `Ensure`. Only a regular file counts. Thumbnails are cached per server (`library.CacheID(server, path)`), written atomically, and served `private`.
- Encodes pass `-abort_on empty_output_stream`, and clips and previews drop the source's metadata and chapters (`-map_metadata -1 -map_chapters -1`). On FFmpeg 9 `-map_metadata -1` drops per-stream tags too, which a real-ffmpeg test checks.
- An ffmpeg run's deadline is `ffmpeg-timeout-sec`, or with the default of 0, the larger of 30 minutes and 20 times the clip's length, or 60 times for an HEVC video encode (`encodeDeadline`), because x265 at the slow preset runs several times slower than x264. A run stopped at its deadline returns `ffmpeg.ErrTimeout`, whose message names the setting.
- Black-bar trim uses `cropdetect=limit=24/255` after `format=yuv420p`. A bare `24` is 24/65535 on FFmpeg 9 10-bit HDR and misses letterboxing.
- Create, update, and preview check a selection through `library.MediaSource.CheckEdit`, which probes once and applies `clip.Edit.Validate`: the `max-clip-dur` cap, the source's end, and an audio track the source carries. A JSON mark below zero is refused when the request is parsed.
- A video clip's Keep HDR (`PreserveHDR`, shown as **HDR** in the profile editor) is the only HDR switch, and it is a clip profile setting (`clip_profiles.keep_hdr`): no export form offers it. On keeps the source transfer (10-bit PQ/HLG, no tonemap), encoded as HEVC Main 10 (`libx265`) in an `hvc1` track at the profile CRF + 1 with the profile preset. Its color tags go in `-x265-params` as well as the output flags, because FFmpeg does not pass them on to libx265 for an untagged input, and PQ alone adds `hdr10-opt=1`. The source's HDR10 mastering display and light level data pass through unchanged, which a real-ffmpeg test checks through a crop and a scale, so never hard-code `master-display` or `max-cll`. Everything else is 8-bit H.264. Off tone-maps on CPU with `zscale`+`tonemap=mobius` to 8-bit BT.709, encoded and tagged with the BT.709 transfer (1-1-1), which upload sites and editors expect. GIFs and JPEGs are encoded with the sRGB transfer, because neither format carries a tag. A tone-mapped clip carries no mastering display or light level data, which a real-ffmpeg test checks on FFmpeg 8 and later. A clip takes its profile's `keep_hdr` through `profile.Preset` whenever it renders: on create, and on an update that regenerates, changes the type, or reaches a clip still waiting. Any other update keeps the stored value, so it always describes the clip's file. Built-ins: 4K HDR and Original on, 720p, 1080p, and 4K off. A JSON request or edit carrying `preserveHdr` or `webSafeColor` is refused with `clip.ErrHDRIsAProfileSetting`, and a form never posts either. `server start` warns when `OUTTAKE_WEB_SAFE_COLOR` or `OUTTAKE_PRESERVE_HDR` is still set. GIFs and screenshots always tone-map an HDR source, between the crop and the scale, because neither format can carry HDR. The PQ peak comes from the source's MaxCLL, then its mastering display peak, read from ffprobe's stream side data, so clips of one title share their exposure. Without either, sample luma with `format=yuv420p` before `signalstats`, so the peak math sees 8-bit limited codes, and use that measured luma. Leave libplacebo (Vulkan/GPU) out. A preview of a clip that keeps HDR is tone-mapped unless the export form's script marked the browser as able to show it (`screenHdr`: the `video-dynamic-range` or `dynamic-range` media query matches and `canPlayType` accepts HEVC Main 10), and its format badge names it. An HDR preview is HEVC like the clip. The preview id follows what the render does. A video clip that keeps HDR from an HDR source renders an SDR version after its own file, in the same job: H.264 tone mapped no wider than the maximum preview width, CRF 23 veryfast, with the clip's crop, which is detected once for both encodes, and audio track. It is stored beside the clip as `<id>.sdr.mp4` (`clip.SDRPathFor`), uploaded, and served from `/clips/:id/sdr?v=`. The queue's `SetStage` moves the job to `clip.StageSDR`, whose progress counts from zero, and the card shows a second bar. The clip stays processing until both encodes finish. A failed SDR version is removed and the clip still completes, unless the job was stopped. A render that needs no SDR version removes a stale one, and a type change and a delete remove it too. A card with an SDR version plays it, and `app.js` moves the player to the HDR file only where the screen shows HDR and the browser decodes HEVC Main 10. The card carries `data-clip-id` and `data-hdr-version`, and the script builds the HDR file's URL from them on the fixed `/clips/:id/file` path rather than reading a URL from the page. An HDR clip without one (`data-sdr-missing`) says so on such a screen. A clip card whose video the browser cannot decode says so, from the video's `error` event. Each video clip file's width, height, and HDR flag (`clip.Format`) are probed as it publishes and recorded through the queue's `SetOutputFormat` and `SetSDRFormat`, and a clip that no longer has an SDR version records a zero one. Players show `Format.Label`, such as "HDR · 4K", in the top-left corner of the player's frame (`components/player`), naming a size within 2% of an export resolution's width or height as the profile editor does, so a 4K clip with its black bars trimmed is still 4K, and any other size as width×height. A card with an SDR version renders both badges and the script swaps their visibility with the source. A clip whose file was never read shows no badge. A preview's format is read when it renders or is reused, while the file is local, and reported as `format` by its status. Web-safe color is retired: `web_safe_color` is written as the inverse of `preserve_hdr` and never read.
- A clip profile's `copy_video` (migration 012, `clip.QualityPreset.CopyVideo`, shown as **Copy the source when possible**) lets a video clip copy its source's video instead of encoding it. `ffmpeg.CopyFits` allows it only when the source is what the encode would produce: 8-bit 4:2:0 H.264 for SDR, or 10-bit 4:2:0 HEVC for an HDR source the profile keeps HDR for, no wider than the profile's maximum, with no crop, and never Dolby Vision. The probe reads `PixelFormat` for this. Audio is copied only when it is AAC with at most two channels, and is otherwise encoded as an encoded clip's is. The copy starts on the keyframe `probe.KeyframeBefore` finds at most `copyReach` (5 seconds) before the start mark, read from packet flags and rounded up to the millisecond, so a regenerate from the recorded start finds the same keyframe. Where a stream-copy seek lands depends on the demuxer: Matroska lands a seek that names a keyframe on the one before it, so `CopyClip` reads where a seek lands with `framecrc` and seeks a little past the keyframe until it lands on it. It then checks the copy's length against the planned one and decodes its first 2 seconds, and refuses a copy that is off (`ErrCopyMismatch`) or does not decode cleanly (`ErrCopyUnclean`), as an open GOP H.264 keyframe's leading frames do. A copy that does not fit, finds no keyframe, would pass `max-clip-dur`, or is refused is encoded instead, with the marks unchanged. A copied clip's window moves to the keyframe, recorded through the queue's `SetWindow` beside `SetOutputFormat`, so a failed render never records it, and its SDR version renders the same window. The status region carries `data-clip-start` and `data-clip-duration`, and `app.js` copies them into the card's form after a swap unless the start field is being edited. Built-in Original copies, keeps HDR, and otherwise encodes like 4K HDR.
- `library.MediaSource.CheckEdit` refuses a Dolby Vision source with no displayable base layer (profile 5, or base layer compatibility id 0), read from ffprobe's DOVI configuration record. ffmpeg decodes only the base layer, which for profile 5 is in Dolby's own color space.
- Export max resolution is a clip-profile setting (720p, 1080p, 1440p, 4K). The built-in profiles are rows like any other, named after what they produce and stored under generated ids by migration 010: 720p (CRF 21, medium, 160 kbps), 1080p (CRF 20, medium, 192 kbps, the default), 4K (CRF 18, slow, 256 kbps), and 4K HDR (4K's settings, keeping HDR). No profile id is fixed in code. `clip.DefaultPreset` holds the 1080p settings for a render with no database or a clip whose profile is gone, and an empty quality means the stored default profile. Every preview, a form's preview and a clip's SDR version alike, is scaled no wider than the **Maximum Preview Resolution** (720p, 1080p, or 4K, default 1080p), stored in `app_settings` as `max_preview_width`, read through `playback.MaxPreviewWidth`, and edited under **Settings → Previews**. A narrower source keeps its width. A form preview's id includes the maximum, so changing it renders the next preview at the new size. GIF scale widths are even, because the chain ends in `yuv420p`.
- `clip.Clip` is the editable record. `clip.Job` embeds it and owns `InputPath`, `OutputPath`, `Status`, `Progress`, and `Error`.
- plex.tv calls decoded as XML (`/api/resources`, `/search`) send `Accept: application/xml`. JSON calls stay on `doRequest`. Every plex.tv GET goes through `requestPlex`, which turns a failure status into `plex.ErrPlexError`, and a 401 also into `plex.ErrUnauthorized`, so no error page reaches a decoder. Live sessions come only from the bound server (`GetSessionsOnServer`), never from plex.tv.
- `RemapMediaPath` treats the Plex root as a directory boundary, so `/data/media` does not claim `/data/media-other`. A mapping that would leave `LocalMediaRoot` is empty. A Windows path (a drive letter, or a UNC share written with backslashes) has its backslashes turned into slashes, matches the root without regard to case, and without a root loses its volume.
- `max-clip-dur` and `session-poll-sec` are second counts. An environment value arrives as a string and still means seconds.
- The clip queue keeps its own copy of every job and hands workers snapshots. Waiting jobs are ids in submission order, so `Submit` and `Requeue` never block. Status and progress reach the database through the queue's status callback, which reports one change at a time and always writes the latest state. A started worker takes a waiting job at once, so a test that looks at a job, or at its pending report, before a worker has it submits before `Start` or keeps every worker busy first.
- Persisted clips reload before the server listens, unfinished ones oldest first, so every request sees every clip and a delete cannot be undone by a late reload.
- `num-workers` is clamped to at least 1 when configuration loads.
- Clip edits go through `catalog.Update` or `catalog.UpdateAndRegenerate`, which change the queue's entry and save it through the queue's ordered report path, so every read and the next start see the edit. A rendering clip only takes a change `clip.RendersLike` calls equal, such as a rename. A type change renders the clip again, and a finished render removes the clip's files for the other types. JSON edits decode into `clip.EditRequest`, where an omitted field keeps the stored value. Clip cards post hidden copies of settings they do not show. Every clip card, on the media page, on `/clips`, and swapped in after a save, is filled from its own probed source through `view.ApplySource`, so an HDR source always offers the HDR checkbox. `/clips` probes its sources through `MediaSource.DescribePaths`, four at a time, on top of the probe cache. `/clips` and a title's clip list (`/media/item/:id/clips`) show `catalog.PageSize` (24) cards a page, picked by `catalog.Window` after filtering and sorting, and only a page's own clips are checked in storage and probed. The list ends with a `clipcard.MoreClips` sentinel (`hx-trigger="revealed"`, `outerHTML`) whose address (`view.MoreClipsURL`) carries the filters, sort, Shared view, the last clip shown (`after`), and the offset. A request whose HX-Target is the sentinel (`routes.TargetClipListMore`, `routes.TargetItemClipsMore`) gets the next cards and the next sentinel, never the empty-list message. Under a sort by creation the next page follows the `after` clip, so a clip made meanwhile repeats no card. Under a sort by name, which a rename changes, or by modification, which a render changes, or once that clip is gone, it starts four clips before the offset (`pageOverlap`), so a shown clip that moved down or was deleted hides no card. After a sentinel's swap, `app.js` drops a card that arrives twice within that list (`data-clip-card`), and `live.js` follows the added cards. Each card the viewer may change carries a `data-bulk-select` box (`name="id"`), and each list's first page starts with a `clipcard.BulkBar` (select all, the count, and the actions, which `app.js` shows while a card is selected). Its buttons post `POST /api/clips/bulk` (`clip.Handler.Bulk`, an action and up to 200 clips, a form with repeated `id` fields or JSON `{"action","clips"}`), and Retry Failed posts `POST /api/clips/retry` with an optional `mediaId`. Each clip goes through the single-clip path: `catalog.Job` scope (another account's clip is skipped), `deleteJob`, `Queue.Cancel`, `catalog.Share`, or `regenerateStored`, which checks Plex access, takes Keep HDR from the profile, validates the edit, and admits it through `quota.Enforcer.AdmitClip`. A regenerate stops at the first reached limit, and the rest count as not started. An htmx caller gets the status line (`bulkMessage`), which goes to a `clipcard.BulkStatusLine` outside the list, and `app.js` then submits the list's toolbar form so the list refreshes with its filters. An API caller gets `api.BulkResponse`.
- Auth has one owner, the account that owns the bound server, plus admins and members. The first Plex account to sign in claims the `users` row with role `owner`. When `plex_tokens` holds a token, only the account behind the newest one may claim. Once owned, an account the bound server is shared with (its own resources list the bound machine, `identity.Auth.ServerToken`) is stored as pending (`users.approved = 0`, migration 014, which `UserRole` reports as `pending`), and `AuthGuard` holds a pending caller at `/pending`, refusing `/api` with `api.Pending`. Every account but the owner must still reach the server at each sign-in, and plex.tv failing to answer refuses with `identity.ErrAccessUnverified`. `identity.Auth.SignIn` refuses every other account and never stores or binds a refused or invalid token. **Settings → Users** (`handlers/users`, behind the admin guard) approves, rejects (deletes the row only while it is still pending, so the account can ask again), removes (clips are kept), changes roles, and sets limits, and every change checks `identity.User.May`: nobody changes the owner, only the owner grants or removes admin, and an admin approves pending accounts and removes or limits members. `AuthGuard` records whether the caller manages the installation in the render context (`view.ContextWithManager`), and the layout shows the admin settings only then. Render limits live in `clip/quota`: concurrent renders (clips waiting or rendering plus unfinished previews, `Queue.CountActive` and `preview.Service.Active`), renders started in a rolling 7 days (`render_log`, in Unix seconds, whose rows older than the window the session sweeper deletes), storage (`clips.output_bytes`, the clip's file and SDR version measured when a render finishes), and the longest clip, each global in `app_settings` (defaults 2, 100, 25 GB, and the installation's maximum) and overridable per user, where NULL takes the global value and 0 sets none. `quota.Enforcer.AdmitClip` holds one lock across the check and the submit for create, regenerate, and a type change, and logs the render only after a successful submit. `AdmitPreview` counts only concurrent renders. A nil enforcer refuses members, the owner and admins are exempt (`middleware.RenderMember`), and `router.wireLimits` hands one enforcer to the clip and preview handlers. A reached limit answers 429 `api.LimitReached` with a message from `failure.Classify`. `outtake owner reset` deletes every user, keeping clips. Sessions only gain a token through sign-in. The session carries the token and `plex_user_id`, and `middleware.AuthGuard` resolves that id against `users` on every request, so deleting the row (`outtake owner reset`) revokes every session. It records the user and its role as the request's caller (`middleware.Caller`), and the e2e environment's caller is the owner. `middleware.AdminGuard` follows it on the pages and actions that manage the installation (Servers, Clip Profiles, Previews, Storage, Users), which answer a member with `respond.ErrAdminOnly`. Logout ends one session. **Forget server** clears the binding. Only a server the signed-in account owns can be bound: discovery (`Auth.Discover`) lists only servers whose plex.tv resource reports `owned=1`, and a shared server's token reaches only what is shared with that account. A server is bound before anyone owns the installation only through the configuration, and then only an account that owns it may claim the installation. The binding stores the server's machine id, and a sign-in by the account that owns the bound server replaces its token with the one plex.tv reports for that machine, keeping the bound connection. Any other account's sign-in leaves the token alone. Every clip belongs to the plex.tv account that made it (`clips.owner_id`, migration 013, which gave older clips to the owner), set from the caller on create and never changed by a save. `middleware.ClipScope` turns the caller into a `clip.Scope`: a member reaches their own clips and previews, and the owner and admins reach everyone's. The catalog applies it in one place (`catalog.Jobs`, `catalog.Job`, `catalog.ForMedia`), so another account's clip is left out of lists and reads as missing by id, the same 404 an id nothing uses gets. A preview id names its owner (`u<plex id>-` and 40 hex characters of the content digest, `preview.OwnedID`), so two accounts never share a preview and every by-id preview route checks `preview.Owner` against the scope. A preview id without an owner, from before ids named one, is reached only by the owner and admins. `/live` starts each feed with the caller's `middleware.Viewpoint`, their scope and Plex viewer. Plex is read as the caller (`middleware.PlexViewer`, an `identity.Viewer`): the owner with the bound server's token, and anyone else with their own token for that server, which `identity.Auth.ServerToken` finds in their plex.tv resources at sign-in and the session keeps (`identity.SessionKeyServerToken`, with when it was checked). `AuthGuard` asks plex.tv again for a missing token at most once a minute and for a held one every 10 minutes, signing the session out when plex.tv no longer lists the server for the account, so a removed share ends within 10 minutes, and keeping the held token when plex.tv cannot be asked. A non-owner without one reads nothing and never falls back to the bound token, and `MediaSource.CheckAccess` refuses a server that comes back carrying any other token. Library browsing, search, item pages, and posters go through `Auth.ClientAs`, so Plex's sharing decides what each account sees, and the library, added-at, and poster caches are keyed by `plex.ViewerKey`, the server plus a digest of the token. File paths are still resolved with the bound token, so create, update, and preview first call `library.MediaSource.CheckAccess`, which fetches the item with the caller's token and refuses a 404 with `library.ErrNotShared` (`api.NotShared`), because a render reads the file from disk with the owner's access. A media page a member cannot load is never probed with the bound token. Sessions carry the playing account's plex.tv id (`plex.Session.UserID`, 1 for the owner on a local server), and the dashboard, the playback panel and feed, the position route, and `/api/sessions` keep them to the caller's scope through `plex.SessionsWhere`. The session monitor still polls with the bound token. `TestNewKeepsAMemberOutOfTheOwnersClipsAndPreviews` sends the owner's ids to every clip and preview route as a member, so a new route that skips the scope fails it. A clip's owner, the owner, or an admin can share it (`clips.shared`, migration 015, through `POST /api/clips/:id/share` and `/unshare`, `catalog.Share`, and the queue's `SetShared`). The scope splits into two lookups: `catalog.Job` finds a clip the caller may change, and `catalog.Viewable` also finds another account's shared clip when `library.MediaSource.Sees` reports that the caller's own Plex token sees its title. `Sees` asks the way `CheckAccess` does and remembers a definite answer for 5 minutes, keyed by the viewer's server token and the media id, and a failure to ask reads as not seen and is not remembered. The read routes (`/clips/:id/file`, `/sdr`, `/row`, `/api/clips/:id/status`, `/download`, and the live clip feed) use `Viewable`, and every change route uses `Job`, so a refused clip reads as missing either way. `TestNewShowsAMemberOnlyTheSharedClipsTheyMaySee` holds the list of read routes (`clipReadRoutes`), and every other clip route must refuse a shared clip. A card for a clip the viewer may not change is read only (`view.Audience`, which sets `ClipItem.ReadOnly`, `CanShare`, and `OwnerName` from the scope and `DB.Usernames`): no form, only playback and Download, naming its maker, or "Former user" once the account is gone. Share and the clips page's **Show** choice appear once a second approved user exists (`DB.Usernames` leaves out pending accounts). `/clips?show=shared` lists `catalog.Shared`, every shared clip the caller sees, and a title's page lists other accounts' shared clips of it under **Shared Clips** (`catalog.SharedForMedia`). Each asks Plex about a title once, at most four at a time. `/api/clips` and the dashboard list only the caller's scope. A shared clip counts toward its maker's storage, and previews are never shared. A binding stored without a machine id is identified through its `/identity` first. A PMS 401 wraps `plex.ErrUnauthorized`. The session monitor warns once per distinct failure, and the dashboard and servers page show a notice while the bound server refuses its token.
- `middleware.HostGuard` answers 421 to a Host that is not an IP literal, localhost, a dotless or private-suffix name, the public base URL's host, or listed in `allowed-hosts`. Tests that drive the router through httptest (Host `example.com`) set `AllowedHosts: "example.com"`.
- Pages send `Cross-Origin-Opener-Policy: same-origin-allow-popups`, and the Plex callback page (`/api/auth/callback`) sends `unsafe-none`, so the sign-in popup keeps its opener on the way back from Plex, which sends none. A stricter value on either page cuts the popup off, which a browser test confirmed. `login.js` polls `/api/auth/status` only once the popup is open, and stops when the PIN's `expiresIn` lapses.
- The playback panel reads the session monitor's cache. Its mark buttons read `/media/item/:id/position?session=<id>` when clicked, for the session the panel shows and never another client on the same item, which asks the bound server's `/status/sessions` directly through `identity.Auth.LiveSessions` within 3 seconds, and fall back to the panel's offset. Only the newest read for each mark is applied, and a sign-in attempt stops the polling of any earlier one. A paused client's position is exact. A playing one is as old as the client's last report to Plex, so the panel advises pausing.
- The media page's export form takes keys in `media-item.js`: I and O mark the start and end from the loaded preview's position, or otherwise click the Plex panel's mark buttons, which read a fresh position, and P clicks Preview. The letters never act while focus is in a field or with Ctrl, Alt, or Meta held. Up and Down in the start or end field nudge it by 0.1 s, or 1 s with Shift. Every mark change, by key or button, is announced in the `#mark-announcement` status region. The buttons name their keys in a `title` tooltip and `aria-keyshortcuts`, and no text on the page lists them.
- `app.js` sets up each export form once (`data-export-ready`), so a swap elsewhere, such as the playback refresh, never touches it. A submit holds every export button on its form (`data-submitting`) until the page is shown again or its htmx request ends.
- The e2e environment skips the auth guard, so `app.New` refuses it on a non-loopback listen address.
- Logging is configured once in `cmd/server` (and the e2e harness), not in `app.New`. Tests build many apps in parallel, and rewriting zerolog's globals while another app logs is a data race.
- **Settings → Storage** (`handlers/storage`) measures the local folders through `blob.Paths.Usage`, which counts finished files only, leaving out staging files and GIF palettes, and reads a missing folder as empty. `blob.FreeSpace` reads the volume through `syscall.Statfs` on Linux and macOS and reports nothing elsewhere, so the page leaves the line out. Clear Previews calls `preview.Service.ClearFinished`, which drops every finished preview from the registry, both its entry and its order, so its status reads as gone, and deletes every preview file that is not rendering, including ones from earlier runs. Clear Thumbnails calls `blob.ClearThumbnails`. Both delete through the `Blob`, so S3 objects go too, `blob.ClearLimit` at a time. Clips are never deleted from the page. On S3 the page counts the local copies and says so.
- `preview.Service.Close` cancels running previews and waits for them, and `App.Close` calls it before the database closes. A completed preview that retention evicts has its file deleted.
- Sessions persist in the `sessions` table through `database.SessionStore`, and CSRF tokens live in the session, so both survive a restart. `app` sweeps expired sessions, and `App.Close` waits for the sweeper to stop before it closes the database, because a connection still running a query when the database closes is released later, and SQLite then touches the database's files after the close has returned. `/assets` (including a missing asset, which answers 404) and `/api/healthz` are mounted before the session middleware, so they never create a session.
- The Fiber app runs with `Immutable: true`, so strings read off a request (`Params`, `FormValue`, `Query`) are copies a handler may keep. It also sets a read and an idle timeout, and no write timeout, because downloads and ranged video stream for as long as they need.
- Static files are embedded by `internal/web/assets`. Pages link them through `assets.URL`, which adds a `?v=` content hash. A request carrying the current hash is cached for a year, and any other is served `no-cache`. Text assets are compressed. Never hard-code an `/assets/` URL in a template.
- Clip files, downloads, and previews go through `respond.SendRangedFile`, which opens the file on every request, skipping Fiber's handle cache, and sends `Cache-Control: no-cache`. A regenerate moves a new file into place under the same path, so clip cards link the file as `/clips/<id>/file?v=<version>`, versioned by the clip's `UpdatedAt`, which every finished render advances. Chromium reuses media it loaded for a URL within a page without revalidating.
- Library lists are cached per server for a minute in `library.LibraryCache`, which the sidebar and every browse fragment share. Callers that miss together share one request, and a slower, older answer never replaces a newer one. A failed request is not cached.
- The media page reads an item's metadata once. `GetMediaItem` carries the file path in `MediaItem.FilePath` (never serialized), and the page probes that path rather than resolving the id again.
- Vendored HTMX is v4. Partials are `<template hx type="partial" hx-target="...">`. A non-JSON error sets `HX-Reswap: none`, because every status other than 204 and 304 still swaps. The failure event is `htmx:response:error`.

## Layout

`internal/` is grouped by seam:

- `clip/` is the clip record and the render job. `clip/profile`, `clip/catalog`, `clip/preview`, `clip/queue`, and `clip/quota` sit under it.
- `timecode/` is the shared duration type.
- `ffmpeg/` runs ffmpeg and ffprobe, with `probe/`, `crop/`, `progress/`, and `tonemap/`. `ffmpeg/ffmpegtest` holds the fakes tests run in their place.
- `plex/` is the Plex client, with `decode/`, `session/`, `library/`, and `identity/`.
- `api/` aliases `clip.Request` and `clip.Response`. Error codes and the other response payloads stay in `api`.
- `web/` is templ and htmx: `view/`, `pages/`, `components/`, `routes/`, `respond/`, `theme/`, `exportform/`, and `handlers/` (`library`, `clip`, `preview`, `server`, `auth`, `profile`, `home`, `health`, `live`, `storage`, `users`). Handler packages match those directory names. Alias domain imports `clipdom`, `clippreview`, and `clipprofile`. `router.go` imports the handlers as `clips`, `previews`, and `profiles`. E2E packages under `testing/e2e/{clips,profiles,previews}` stay plural.
- `store/database` and `store/blob` are the database and the filesystem/S3 adapters.
- `settings/config` and `settings/flags` are process configuration and CLI flags.
- `app/` wires the concrete runner, client, database, and blob store. `cmd/` only binds flags and starts `app`. `logging/` and `metadata/` stay at the root.

Outside `internal/`, `tools/docgen` is a command in the main module that writes the CLI reference, and `docs/` is the documentation site, in its own module.

No package under `clip/`, `ffmpeg/`, `plex/`, or `store/` may import `internal/web`. `web` and `cmd` are the edges: handlers decode, call one domain function, then encode. `app` is the only place that knows which backend is wired, and it passes that wiring to `web.New`.
